# YOLOv5 目标检测训练完整实践

> 计算机视觉落地最难的不是训练模型，而是"从真实场景数据到可用模型"的完整链路。本文复盘一次巡检设备目标识别的落地全过程。

## 业务背景

巡检场景里，工作人员需要对调压箱、井盖等设备拍照，但现场拍照不规范、漏拍错拍多，靠人工检查难以有效约束。

我们的方案：引入目标检测，让系统自动识别照片里的巡检设备，判断"拍没拍到、拍得对不对"。

## 数据：比算法更重要的一环

目标检测的效果，六成以上取决于数据。我们经历了完整的**数据工程**流程：

1. **采集**：从真实巡检现场收集约 2 万张设备照片
2. **筛选清洗**：剔除模糊、重复、角度异常的照片
3. **标注**：用标注工具框出目标（调压箱、井盖等类别）

几个关键经验：

- **类别平衡**：各设备类别的样本量要均衡，样本少的类别要多采
- **负样本**：要有"没有目标"的照片，否则模型会"硬框"一个目标出来
- **难例挖掘**：专门收集模型容易认错的照片补充训练

## 训练与调优

基于 YOLOv5，训练的关键点：

```python
# 核心超参数
epochs = 300
batch = 32
img_size = 640
```

调优要点：

- **数据增强**：mosaic、随机缩放、色域变换，提升泛化能力
- **迁移学习**：用 COCO 预训练权重初始化，再在业务数据上微调
- **评估指标**：重点关注 mAP，同时看每一类的 AP，定位"哪类设备识别差"

## 多端部署

训练好模型只是第一步，部署才是真正的挑战。针对不同项目的硬件条件，我们提供了多套推理方案：

| 环境 | 方案 |
|------|------|
| 服务器（GPU） | PyTorch + CUDA，高吞吐 |
| 服务器（CPU） | ONNX Runtime，纯 CPU 推理 |
| 边缘（NPU） | 转成 NPU 支持的格式 |
| 移动端（Android） | 模型转 TFLite/NCNN，离线推理 |

## 小结

目标检测落地是一条长链路：采集 → 清洗 → 标注 → 训练 → 评估 → 多端部署。算法只是其中一环，**数据质量和部署能力**往往才是决定项目成败的关键。这套"从数据到落地"的完整经验，比会调一个 YOLO 训练脚本有价值得多。
