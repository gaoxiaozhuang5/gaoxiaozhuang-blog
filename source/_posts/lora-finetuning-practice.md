# LoRA 微调企业场景模型

> 通用大模型在垂直场景上往往"差一口气"。LoRA 提供了一种低成本、可落地的微调方案。本文记录一次企业场景微调的完整过程。

## 为什么是 LoRA 而不是全量微调

全量微调要更新模型所有参数，7B 模型就需要几十 GB 显存，普通团队根本玩不起。

**LoRA（Low-Rank Adaptation）** 的思路很巧妙：冻结原模型，只训练一小部分低秩矩阵。带来的好处：

- **显存小**：7B 模型一张消费级显卡就能微调
- **训练快**：参数量是原来的几百分之一
- **即插即用**：微调结果是"附加参数"，可以随时挂载/卸载

## 数据准备：微调质量的决定因素

微调效果 80% 取决于数据。企业场景的数据准备要点：

1. **格式**：指令微调用 `{"instruction": ..., "input": ..., "output": ...}` 格式
2. **质量**：少量高质量数据 > 大量低质量数据，宁缺毋滥
3. **覆盖**：要覆盖真实场景的边界情况，不能只给"标准问法"

## 训练实践

以 Qwen2.5 为例，LoRA 微调的关键参数：

```python
lora_config = {
    "r": 16,              # 低秩维度
    "lora_alpha": 32,     # 缩放系数
    "target_modules": ["q_proj", "v_proj"],  # 只微调注意力层
    "learning_rate": 2e-4,
}
```

显存估算有个经验公式：

```text
显存 ≈ 模型权重 + 优化器状态 + 激活值
7B 模型 LoRA 微调 ≈ 16~24 GB（取决于 batch 和序列长度）
```

## 效果评估

微调完不是"看起来不错"就行，要量化评估：

- **构建评测集**：从真实场景抽取几十上百条典型问题
- **对比基线**：微调前后在评测集上对比准确率
- **防止过拟合**：留一部分数据做验证集，监控训练和验证的 loss 差距

## 小结

LoRA 让"微调大模型"从大厂专属变成了普通团队的可行选项。但记住：**数据质量 > 训练技巧**。把精力花在整理高质量、覆盖真实场景的数据上，比调参数重要得多。
