# 多 Agent 协作与工具权限控制

> 单 Agent 能力有天花板，复杂任务需要多个 Agent 分工协作。但 Agent 越多，越要警惕一件事——权限与安全。本文聊透这两个话题。

## 为什么需要多 Agent

单 Agent 把所有能力塞给一个模型，会带来几个问题：

- **上下文爆炸**：任务越复杂，塞给单个 Agent 的指令越多
- **能力冲突**：一个 Agent 既要做规划又要做执行，容易顾此失彼
- **难以复用**：不同场景的 Agent 无法独立迭代

多 Agent 的思路是**分工**：不同 Agent 各管一段，通过协作完成复杂任务。

## 常见多 Agent 模式

### 1. 规划者 + 执行者

一个"规划者" Agent 负责拆解任务，多个"执行者" Agent 各管一块：

```text
用户复杂任务
   ↓
规划者 Agent：拆解成子任务
   ↓
执行者 Agent A（查数据）+ 执行者 Agent B（生成报表）+ ...
   ↓
汇总
```

### 2. 流水线模式

按处理顺序串联多个 Agent，上一个的输出是下一个的输入。适合文档处理、审核这类"多环节"任务。

### 3. 辩论/评审模式

多个 Agent 对同一问题给出不同答案，再由一个评审 Agent 综合，用于提升质量。

## 工具权限：多 Agent 最容易被忽视的坑

Agent 要调用工具（查数据库、调 API、执行操作），但**工具权限必须受控**。一个血泪教训：

> Agent 有权限执行任意 SQL，用户问了一句诱导性的话，Agent 就把一张表删了。

生产环境的权限设计要点：

1. **最小权限**：每个 Agent 只授予完成任务所需的最小工具集
2. **只读优先**：默认只给只读工具，写操作单独授权
3. **用户身份传递**：Agent 调工具时带上当前用户身份，数据权限按用户过滤
4. **危险操作拦截**：删除、批量修改等危险操作需要人工确认

## 小结

多 Agent 协作是提升 AI 能力上限的重要手段，但**能力越大，权限越要收紧**。一个可靠的 Agent 系统，一半功夫在"让它能干活"，另一半功夫在"让它不会乱来"。工具权限控制，是多 Agent 走向生产的必修课。
